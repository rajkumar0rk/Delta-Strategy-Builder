# Shared futures/options BTC pullback research — Options opt-in (November 2026)

This option-mode implementation reuses `backend/app/futures_setups.py`'s completed HTF EMA/ATR setup snapshots and the market-neutral `backend/app/shared_execution.py` pending-stop, 1H trend, daily-risk and session clock helpers. The OPTIONS engine retains its own contract selection, quote execution, premium P&L and Delta option fees/GST. It does not route through futures execution or use futures funding, quantity, margin or liquidation.

## Configure in Strategy JSON
Import `visualizer/backend/examples/btc-options-intraday-pullback.strategy.json` (schema 15), or use `options_pullback.enabled=true`, `market_type=OPTIONS`, `timeframe=5m`, `position_policy=EXCLUSIVE`, and only enabled BUY CALL/PUT directions. SELL option positions and pattern_trade cannot use this research mode (option-premium downside and naked shorts have different/unbounded risk). Add non-chart-only `EMA(20)` and `ATR(14)` on the selected setup timeframe (usually 15m); optionally three confirmed 1H EMA50/200/1 sources and 5m volume SMA. The configured indicator IDs must match exactly. `trend_crossover_block_bars`, `cancel_on_trend_invalidation`, `require_touch`, `require_confirmation_color`, `require_volume`, `volume_multiplier` and directional entry/no-trade rule trees are configurable.

Set `options_pullback.execution_mode=STOP_MARKET_INTRABAR`, `stop_anchor=SIGNAL_CANDLE`, `max_wait_bars=6` next 5m candles, `breakout_buffer_ticks=1`, `underlying_tick_size=0.5` (assumption), `stop_buffer_atr=0.1`, `reward_r_multiple=2`, `size_mode=RISK_EQUITY`, and `equity_risk_percent=0.5`. Configure entry `session.windows=14:00–21:59` Asia/Kolkata and independent `options_force_exit_time=23:45`. Set option `risk.stop_loss.mode=NONE`, `risk.take_profit.mode=NONE`, `risk.profit_protection.mode=NONE`, `max_hold_minutes=null`; otherwise validation rejects ambiguous exits. `risk.max_daily_loss_percent=1` sets daily realized net loss limit and also constrains new trade estimated premium-at-risk.

## Semantics and limitations
A completed 15m setup freezes its BTC trigger level and signal-candle (or prior swing) ATR stop. One pending entry may arm; a subsequent 5m BTC candle with high/low through the trigger is recognized **only at that candle close**, never as a true historical intrabar option execution. At that time the engine selects a real option contract and requires an eligible, non-expired option quote; BUY is ask + assumed ticks, exits are bid - assumed ticks. No quote means no invented fill. This consumes the pending stop attempt, preserving exclusivity. P&L and Delta option fee-cap/GST are the original OPTIONS calculations.

Protective stop/target are **BTC underlying price levels** and neither implies a 2R option premium outcome nor models delta/gamma/theta/IV. Stops take priority when one completed BTC bar touches both stop and target. A stop/target signal requires a pre-expiry option quote at/after the confirmed BTC bar close; stale or absent quotes cannot be filled. If no valid exit quote is available, the exit remains pending and retries against later quotes. The independent forced clock also attempts a valid quote and never substitutes a BTC price for the option premium.

Sizing uses a deliberately conservative full BUY premium + two estimated fee sides per option unit; excludes hypothetical option Greeks and SELL margin. Rounding respects option contract size_increment, min_quantity, configured max_lots, budget and available cash. Daily risk limit uses starting-day equity and realized net P&L; stop gaps/quote differences and contracts with incomplete quotes can violate realized risk despite pre-entry allowance. Research status is LOW_FIDELITY_SYNTHETIC_BBO when synthetic bid/ask is present. No actual exchange orderbook depth or intrabar time sequencing is available.

## Performance / verification
One-time completed-HTF aggregation, at most one pending order, bounded swing/crossover state and O(1) per-bar order lifecycle. Contract selection uses the existing indexed bounded candidate/quote queries; no duplicated archive or per-bar full-history evaluation. Legacy OPTIONS and FUTURES remain default/unchanged when the new mode is disabled. The options backtest cache version is bumped. Run backend tests, option/futures regression, frontend build, and a real-data frozen holdout before interpreting profitability. Inspect the exact trade markers, rejection counts and unresolved exits.
